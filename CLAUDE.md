## Anatomy

```
blocks/
  cta-button/
  donation-array/
  email-wrapper/
  _TEMPLATE/                    # scaffold for new blocks
  <block>/README.md             # per-block docs (tier 1 + tier 2 walkthroughs)
  <block>/1-basic.html          # tier 1: paste-and-go HTML
  <block>/2-with-cmfs.html      # tier 2: wired to AK Custom Mailing Fields
  <block>/3-personalized.html   # tier 3: per-recipient (donation-array only so far)
  <block>/screenshots/          # generated PNGs embedded in the README
playground/
  index.html                    # vanilla JS playground, served by GitHub Pages
tests/
  screenshots.js                # Playwright renderer for block screenshots
  README.md                     # how to run
BACKLOG.md                      # internal roadmap — block candidates + tooling
.nojekyll                       # disables Jekyll on Pages; we want files served as-is
```

## Tier model

- **Tier 1 — Paste and go.** Edit the HTML directly. No setup. Works on every AK instance.
- **Tier 2 — Let the team edit it from the AK admin.** Variable parts come from Custom Mailing Fields (per-mailing) or Email Wrapper Fields (per-wrapper). One-time admin setup.
- **Tier 3 — Personalize to each recipient.** Amounts or text calculated from donor history. Donation-array only so far.

Not every block has all three. Tier 1 always exists.

## Screenshot pipeline

Block screenshots are generated by `tests/screenshots.js`, which depends on Playwright installed in the global `playwright-skill` (not in this repo). Fragments get wrapped in a minimal email canvas; the email-wrapper full-document block gets its Django/AK template tags substituted with sample content before rendering.

```bash
cd ~/.claude/skills/playwright-skill
node run.js /Users/jordankrueger/ClaudeCode/business/campaignhelp/ak-mailing-blocks/tests/screenshots.js
```

Output goes to `blocks/<name>/screenshots/1-basic.png`. Commit the PNGs alongside HTML changes.

The `preheader` block was removed — AK handles preview text natively via the Compose-screen field and the wrapper's `{{ preview_text }}` template variable. See "Won't build" in BACKLOG.md.

## Playground

`playground/index.html` is pure HTML + vanilla JS, no build step. Loads in any browser. Currently covers donation-array (proof of concept); cta-button and email-wrapper to follow the same pattern. Hosted by GitHub Pages from `main` branch root.

GitHub Pages **requires `.nojekyll`** at the repo root because the block HTML and BACKLOG.md contain literal Liquid tags (`{% if preview_text %}`, etc.) that Jekyll would try to render and fail on.

## Conventions

- Sentence case for headings in READMEs
- Per-block README structure: "What it is" → screenshot → tier 1 walkthrough → tier 2+ if present
- Don't commit large unoptimized PNGs — current screenshots are ~50KB each at 2x density
- New blocks: scaffold from `blocks/_TEMPLATE/`, add to top-level README's Blocks list, and add to `tests/screenshots.js` discovery (it's automatic if you follow the `1-basic.html` naming)
